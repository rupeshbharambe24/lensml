# Demo recording assets (plan §8 D27)

Three VHS GIFs + one 90-second Round 1 video. The GIFs anchor the
README hero; the video lives on YouTube unlisted and is linked from
the README.

## Layout

```
demo/
  install.tape      VHS script — install lensml + first import
  watch.tape        VHS script — start the dashboard + run a watched script
  intervene.tape    VHS script — the magic moment, end-to-end on replay
  scripts/
    demo_train.py   Tiny watched-script that imports lensml.watch (drives watch.tape)
  out/              ← regenerated by `bash demo/record.sh`; gitignored
    install.gif
    watch.gif
    intervene.gif
  RECORDING.md      Playbook for the 90-second Round 1 video (multiple takes,
                    YouTube unlisted upload, README link).
```

## Why VHS

[charmbracelet/vhs](https://github.com/charmbracelet/vhs) renders a
declarative `.tape` script into a GIF deterministically — no manual
keystrokes, no flaky timing, regenerable when the CLI changes. The
3 GIFs in the README hero stay accurate as long as the .tape files
do.

## One-liner regeneration

```bash
# Install vhs once (macOS: `brew install vhs`; Linux: see VHS README).
bash demo/record.sh
```

That writes `demo/out/{install,watch,intervene}.gif`. Drop those into
`README.md` (the slot is already there — see the `<!-- DEMO_GIFS -->`
markers).

## Honest scope

The video itself (90-second Round 1 take, YouTube unlisted upload, README
link) is still a manual step — see `demo/RECORDING.md` for the script,
takes plan, and upload checklist. The .tape files automate the
*regenerable* parts so the GIFs never drift from the actual CLI.
